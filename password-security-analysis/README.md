# Password Security Analysis

Can a lightweight machine-learning model identify weak and predictable
passwords that traditional rule-based checkers classify as secure?

All commands are run **from the repository root**, inside the virtual
environment (`source .venv/bin/activate`).

---

## 0. Setup (once per computer)

```
sudo apt install python3-venv python3-pip -y
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

In every new terminal, before running anything:

```
cd <path>/password-security-analysis
source .venv/bin/activate
```

## 1. Run ONCE (data already frozen in the repo)

These steps create the three samples in `data/samples/`. They are already
in the repository: **do not re-run them**, or both of you will train on
different data and results will not match.

| File | Command | Creates |
| --- | --- | --- |
| `src/data/sample_dataset.py` | `python -m src.data.sample_dataset` | `data/samples/rockyou_sample.csv`, `random_sample.csv`, `challenge_sample.csv` |

Only re-run it if you deliberately change the sampling design. In that case:

1. Agree with your teammate first.
2. Commit the new CSVs.
3. Re-run everything in section 2.

Notes:
- Regenerating RockYou needs `data/raw/rockyou.txt` (never committed).
- Only one sample can be regenerated with `--only rockyou|random|challenge`.
- Random passwords differ on every run (that is intended), so regenerating the random sample changes the results slightly.

After cloning the repo, `data/processed/` and `models/` are empty: run

## 6. Data and labels

**Samples** (`data/samples/`):
- **A.** `rockyou_sample.csv`: 99,997 human passwords from the 2009 RockYou leak, stratified by frequency rank (`very_common`, `common`, `rare`) plus 20,000 rule-compliant ones (`rule_compliant_extra`).
- **B.** `random_sample.csv`: 100,000 passwords from Python's `secrets`. Every one reaches at least 10^14 brute-force guesses, the offline threshold of Florêncio et al. (2014).
- **C.** `challenge_sample.csv`: 1,161 passwords that pass LUDS rules but follow attacker templates. Half use words outside the feature dictionary (`vocab = unseen`).

**Labels** (operational, from the source, never from System A):

| label | label_name | sources |
| --- | --- | --- |
| 1 | predictable | RockYou, challenge set |
| 0 | not_predictable | secure random generator, >= 10^14 guesses |

`stratum` is NOT a label: it only records how each password was sampled.

**Splits** (by `family_id`, so variants like Maria2026! / maria2027 stay together):

| split | content | use |
| --- | --- | --- |
| `train` (80%) | RockYou + random, `fold` 0–4 | training and cross-validation |
| `test` (20%) | RockYou + random | final evaluation, used once |
| `challenge` | challenge set | never trained on; answers the research question |
